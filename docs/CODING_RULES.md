# 编码规范

本规范约束新增和修改的代码。已有代码中与规范不一致的用法，不在无关任务中批量替换；先分析行为、序列化字段和场景引用的影响，再单独迁移。

## 命名与组织

| 类别 | 规则 |
| --- | --- |
| 类 / 方法 | PascalCase，如 `SkeletonEnemy`、`ChangeState()` |
| 公有字段 | camelCase |
| 私有字段 | `_camelCase` |
| 局部变量 / 参数 | camelCase |
| 新脚本文件 | PascalCase，与类名一致，不含空格 |

一个文件一个主要类。沿用项目现有全局命名空间；引入命名空间或自定义 Assembly Definition 前单独说明迁移范围。动画参数须与实际 Animator 一致，不能单独按命名规则修改字符串。

Inspector 参数使用私有序列化字段并按职责分组：

```csharp
[Header("Movement")]
[SerializeField] private float _moveSpeed = 8f;
```

序列化字段改名应评估现有值的迁移，避免场景和 Prefab 配置被重置。

## 状态机

- 实现 `Enter()`、`Update()`、`Exit()`，按基类约定调用 `base`。
- 进入时设置动画和初始数据，退出时清理动画参数、临时标记和资源。
- 状态切换条件明确；完成一次切换后，避免本帧继续使用旧状态逻辑重复切换。
- 状态间数据经实体和已有状态机接口传递，不直接改其他状态内部字段。
- 沿用动画事件桥接；时间驱动状态须说明计时与动画的关系。
- 玩家与敌人当前退出方法均为 `Exit()`；不要把早期副本的 `Exist()` 描述当成当前事实。

## 引用与性能

新增代码禁止：

- `FindObjectOfType`、`GameObject.Find` 和同类全局查找。
- 在 `Update()` 中执行 `GetComponent`；初始化时缓存引用。
- `Invoke` / `InvokeRepeating`；使用明确的计时或协程流程。
- `SendMessage` / `BroadcastMessage`。
- `DontDestroyOnLoad` 或新增单例模式；引用通过 Inspector、既有实体或明确依赖传入。

避免每帧不必要的分配与字符串拼接。历史系统已有全局入口或查找时，需在独立改动中评估替换。

## 战斗、碰撞与动画

- 伤害由受击实体处理；命中检测只负责筛选目标并调用伤害入口。
- 沿用当前实现：近战用范围重叠检测；尖刺 / 出口用 Trigger；玩家地面接触用碰撞回调；墙和敌人地形检测用射线。
- 检测半径、LayerMask、伤害及击退参数保持可配置。
- 核对同一攻击窗口、多 Collider、死亡、无敌与对象销毁边界。
- 动画事件经桥接组件转发到当前状态，不直接跨层操作状态内部数据。
- 复杂逻辑用简短中文注释解释原因；新状态说明职责和触发条件。

## Unity 资源与依赖

- 资源及 `.meta` 成对提交，移动或改名时保留 GUID。
- 场景 / Prefab 修改后核对对象引用、Layer、Tag、碰撞和动画事件。
- 包依赖变更同时审查 `manifest.json` 与 `packages-lock.json`。
- 不提交缓存、个人设置、凭证或构建产物，不批量重写无关资源。
- 新素材记录来源和许可文件，保留第三方声明。

完成任务后执行[验收清单](REVIEW_CHECKLIST.md)，并记录真实验证结果。
